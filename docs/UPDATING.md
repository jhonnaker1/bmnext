# Updating Previous, zlib and Circle

## Previous

Previous is kept in Subversion on SourceForge
(`https://svn.code.sf.net/p/previous/code/trunk`), with no official git
repository, so it is not a submodule: `third_party/previous` holds its
trunk as plain files, at the revision in `third_party/previous/SVN_REVISION`.
`tools/update_previous.sh` exports it (it needs `svn`) and removes what
BMNeXT must not ship: NeXT's ROMs and a ROM disassembly (`src/*.BIN`,
`src/*.ASM`), the NeXTdimension's i860 emulator (`src/dimension/i860*`,
whose header in Previous still has the old MAME licence) and the empty disk
images (BMNeXT's menu makes blank disks itself). It is otherwise used unmodified;
everything specific to BMNeXT is in `src/port/`:

| File | What it has to do with Previous |
|---|---|
| `src/port/previous.mk` | The list of Previous (and zlib) source files to compile, from Previous's `CMakeLists.txt` files |
| `src/port/config.h` | Previous's build options, which its CMake build writes from `cmake/config-cmake.h`; `ENABLE_RENDERING_THREAD` runs its CPU on the main thread |
| `src/port/compat/previous_prefix.h` | Included before each Previous file: headers some of Previous's count on, and declarations newlib lacks |
| `src/port/compat/SDL3/SDL.h` | The SDL types Previous's `host.h` names its locks and threads after |
| `src/port/main_next.c` | Previous's `main.c` without SDL or threads: start up, the CPU loop, `Main_EventHandler()` |
| `src/port/host_next.c` | Previous's `host.h` (`src/gui-sdl/sdlhost.c`) on one thread |
| `src/port/nextbus.c` | Previous's `NextBus.cpp` without the NeXTdimension, and the NeXTdimension's functions as stubs |
| `src/port/enet_next.c` | `enet_slirp.c` without its thread: SLiRP polled from the emulator's event handler, and its DNS server from the kernel |
| `src/port/rpc_sockets.c` | `src/slirp/rpc/csocket.c`, `udpsocket.c` and `tcpsocket.c` without their threads: Previous's NFS, NetInfo and other servers' sockets polled |
| `src/port/bmnet.c`, `compat/bmnet.h` | The BSD sockets SLiRP and the servers use (redirected to `bmnet_*` by macros, `-include`d): 127.0.0.1 in memory, the rest through the kernel's TCP and UDP (`src/host.h`); tested by `tools/hostsim/bmnet_test.c` |
| `src/port/compat/pi/sys/` | `uio.h`, `ioctl.h` and `un.h`, which SLiRP includes and newlib for Circle hasn't |
| `src/port/nonet.c` | `enet_slirp.c`'s functions, with no network (not built; a NeXT without one) |
| `src/port/screen.c`, `audio.c`, `keymap.c`, `gui_event.c`, `statusbar.c`, `dialogs.c` | The same functions as Previous's `src/gui-sdl/` files |
| `src/port/posix_extra.c` | `timegm()`, `scandir()`, `utime()`, `access()`, `chmod()` for newlib |
| `src/port/menu.c` | Changes Previous's settings (`ConfigureParams`) and applies them with `Change_CopyChangedParamsToConfiguration()`, as Previous's SDL dialogs do |
| `src/port/osd.c` | Draws the menu with Previous's font (`src/gui-sdl/font10x16.h`) |

The 68030 and 68040 CPU core's opcode handlers are generated by `build68k`
and `gencpu`, built for the computer doing the build (the Makefile, and
`tools/hostsim/Makefile`), as Previous's own CMake build does.

To move to a newer Previous:

1. Fetch it: `tools/update_previous.sh <revision>` (or with no revision for
   the one in `SVN_REVISION`; `HEAD` for the latest).
2. Compare the source lists in Previous's `src/CMakeLists.txt` and those of
   `src/cpu`, `src/softfloat`, `src/dsp` and `src/debug` with
   `src/port/previous.mk`, and add or remove files. Compare
   `cmake/config-cmake.h` with `src/port/config.h`. Compare the functions
   in `src/gui-sdl/`, `main.c`, `NextBus.cpp` and `includes/host.h` with
   `src/port/`: new functions, changed signatures, new calls at start up.
   Check that nothing new starts a thread (`host_thread_create()`:
   `host_next.c` refuses it and logs it).
3. Build and test on the PC first:
   `BMNEXT_ROMS=<your ROMs> tools/hostsim/run_tests.sh`, and try NeXTSTEP
   in the live simulator (`tools/hostsim/live.sh`). Then build the kernels
   (`./build_sdcard.sh pi4 pi5`) and try them on a Pi.
4. Update the version in `docs/THIRD_PARTY.md`, and commit:

   ```
   git add third_party/previous src/port docs/THIRD_PARTY.md
   git commit -m "Update Previous to r<revision>"
   ```

## zlib

zlib is a submodule in `third_party/zlib`, at a release tag (`v1.3.2`).
Check out a newer tag, compare its source files with `ZLIB_SRCS` in
`src/port/previous.mk`, and update the version in `docs/THIRD_PARTY.md` and
`sdcard/licenses/zlib.txt`.

## circle-stdlib (Circle and newlib)

circle-stdlib is a submodule in `third_party/circle-stdlib`, pinned to the
same revision BMC64 uses. `make_all.sh` applies the patches in `src/patches/`
to Circle before building:

- `circle_sysconfig_patch.diff` enables multi-core and the USB FIQ
- `circle_linux_bug_patch.diff` turns off `BUG_ON`, whose checks in Circle's
  Linux emulation (used by VCHIQ for display and sound) only allow core 0;
  the emulator calls them from core 1, as BMC64 does
- `circle_bolt_keyboard_patch.diff` adds Logitech Bolt keyboard support
  (from BMC64)

To update, move the submodule to a new circle-stdlib release, run
`git submodule update --init --recursive`, then `./build_sdcard.sh`. If a
patch no longer applies, update it from the matching BMC64 patch or by
hand. `src/fbl.cpp` and `src/vchiqsoundbasedevice.cpp` use Circle's VC4
addon and may need the same changes BMC64 makes when it updates Circle.

## The NeXTdimension, later

The NeXTdimension (`src/dimension/`) is left out for now. To add it:

1. Settle the i860 emulator's licence. Previous's copy
   (`src/dimension/i860*`) still says "MAME license, non-commercial"; MAME's
   copy of the same code by the same author (`src/devices/cpu/i860/` in
   MAME) has been BSD 3-clause since 2016. Asking Previous's maintainers (or
   Jason Eckhardt) to confirm, and to update Previous's headers, is the
   clean way; then stop `tools/update_previous.sh` removing those files.
2. Build `src/dimension/` (C++) in place of `src/port/nextbus.c`'s stubs,
   with `nd_sdl.cpp` replaced by a BMNeXT version, and the board's 32-bit
   1120x832 picture copied by `src/port/screen.c`.
3. Run the i860 first in Previous's no-thread mode (`bI860Thread = false`,
   on the emulator's core), then on a core of its own (Circle's cores 2 and
   3 are free), which needs real locks and atomics in `src/port/host_next.c`.
4. The board needs its own ROM (`ND_step1_v43.BIN`), the user's, like the
   NeXT's.
